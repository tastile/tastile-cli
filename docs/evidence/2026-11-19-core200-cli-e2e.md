## 3. 実施した操作と検証した状態

全ての mutation は dry-run → 明示 apply → read-back → DB 直接確認の順。
HTTP 200 / コマンド存在は成功条件にしていない。

### 3.1 source 登録 → read-back → schedule publish

- `schedule publish --from-json publish-daily.json` (dry-run): typed request の
  preview のみ。credential store 読取・network request なし。
- `--apply --idempotency-key 8be8d059-...`: `POST /v1/schedule-definitions`、
  command_id `01a1f3f0-a0a8-...`、accepted_at `2026-11-19T13:13:15Z`、revision 1、result 2。
- read-back: 日次 source ("publish daily") が source list に出現。

### 3.2 placement 生成・read-back

- `source-tiles placements <id>`: 生成済み placement を read-back。
- DB: `v1_placement` の ownership / open 状態を直接確認 (下記各ケース)。

### 3.3 execution start → pause → resume → finish

週次 source (`E2E weekly review`) に対し:

| 操作 | revision | result |
| --- | ---: | ---: |
| start | 1 | 0 |
| pause | 2 | 2 |
| resume | 3 | 2 |
| finish | 4 | 2 |

DB 確認: execution state = 2 (finished 相当)、revision = 4、
execution segment = 3 行。finished placement は自動 reflow から保護される
(Core safety boundary、HTTP 422 で拒否されることを確認済み)。

### 3.4 reflow

- dry-run: owned/open placement = 4/4/4 (owned/open/in-scope)。
- apply: result 1、source revision 1、open placement 4 を read-back。
- finished execution の placement への reflow は 422 で fail-closed (迂回せず)。
- open かつ execution 未 link の source では冪等 `AlreadyApplied`。

### 3.5 lossless update (複雑 plan)

複雑 source (`E2E complex plan gamma`) を作成:

- 9 occurrences / 18 placements、duration 90min、weekday_mask 96、
  window 3h、split policy kind=1 (min 30min / max 60min / max 3 segments、
  実 placement は 0/2・1/2 の 2 分割)、priority 30。
- plan completion: `All[Fact ready Exists, Task 1111... Completed]`、
  tasks 2 件 (draft section / review section、各 complete condition 付き)。

update dry-run は title と priority (30→31) のみを変更提案、
impact = 9 occurrences / 18 placements と表示。
apply → revision 2、18 open placements。

read-back の `definition` で以下が**すべて保持**されることを確認:
tasks の content/complete、completion root、split_policy、window offsets、
weekday_mask、offset_min。occurrence nominal_at は更新で延長され
(最終 occurrence が新規追加)、予定構造は保持。

CLI の注意喚起 (仕様通り): `horizon` は materialization 入力で Core は永続化
しない / relation refs は `existing` に正規化されるため `local` は明示再指定。

### 3.6 cancel と影響範囲

- 単発 source の cancel dry-run: owned/open placement 1 件を表示。
- apply: source lifecycle state = 3 (cancelled)、revision 2、open placement 0。
- 最終 `source-tiles list`: renamed weekly、daily、complex、cancelled、
  default sleep/break が期待通り混在。取消は他 source の placement を
  巻き込まない (他 source の open placement 数は不変)。

### 3.7 today / prompts / timeline

- `today`: 未来の actionable item (休憩、`projected_next_start_at`
  `2026-11-19T13:29Z`) を返却。過去・stale・null の projected start は除外。
- `prompts list`: pending prompt 1 件。
- `timeline` (2026-11-20): EXEC placement 列を表示、open 状態を確認。

## 5. mutation コマンド安全性監査

| 項目 | 実測 |
| --- | --- |
| endpoint | 全 mutation は `/v1/` 配下の対応 endpoint (OpenAPI v3.8.1 pin と一致)。`schedule regenerate` は fail-explicit で unsupported |
| credential | `TASTILE_CREDENTIAL_FILE` は loopback API のみ受理。OS keyring が production 経路 |
| base binding | credential の `api_base_url` が設定と不一致 → 送信前に拒否 (`belongs to a different API base`) |
| expiry | 期限切れ credential → 書込み前に拒否 (`credential has expired`) |
| loopback gate | `TASTILE_ISOLATED_TEST_STACK=confirmed` なしの loopback 書込み → 拒否 |
| reserved port | port 31400 は read 含め全拒否 (`reserved operational port`) |
| revision | update は `--expect-revision` CAS。stale → 409 + current_revision |
| idempotency | `schedule publish --apply` は明示 UUID key 必須。同一 key 再送で重複生成なし |
| owner | credential subject / owner pin は write target 検証の一部として probe される |
